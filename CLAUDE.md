# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Station Egg Hunt is a BostonHacks 2026 (Transit Gamification) hackathon app. Riders photograph small details in MBTA stations as "eggs", and other riders race a timer to find them and photograph them as proof. `README.md` has the full game rules (levels, points, timers, rotation, retiring).

## Layout and commands

An npm workspace: `backend/` (Node API + MongoDB) and `frontend/` (static phone web app, no build step), plus `api/index.js` and `vercel.json` for deploying both as one Vercel project. Needs Node 22.9+.

The backend's runtime dependencies are `mongodb` and `sharp` (image processing, for blurred egg photos), and `mongodb-memory-server` is a dev dependency. Use Node built-ins for everything else (`node:http`, `node:test`, `node:crypto`, global `fetch`), and ask before adding packages. The frontend has no dependencies and no build step.

```bash
npm install                                  # once, at the repo root
npm run dev                                  # local server with --watch; also serves frontend/ on :3000
npm run dev:frontend                         # frontend alone on :5173, pointed at :3000
npm test                                     # backend tests (in-memory MongoDB, nothing to install)
cd backend && node --test --test-name-pattern="full round" test/api.test.js   # one test
npx vercel --prod                            # deploy (project is CLI-deployed, not git-connected)
```

Env vars live in `backend/.env` locally (see `backend/.env.example`) and in Vercel project settings in production: `MONGODB_URI` (empty means a temporary in-memory MongoDB locally, and it is required on Vercel), `MONGODB_DB` (default `egghunt`), `TEST_MONGODB_URI`, `DB_POOL_SIZE`, `CORS_ORIGINS`, `SERVE_FRONTEND`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `MBTA_API_KEY`, `PORT`. There is no linter or formatter.

## Architecture

**Deployment.** On Vercel, `frontend/` is the static output directory, and `/api/*` and `/photos/*` are rewritten to `api/index.js`, which calls `getApp()` from `backend/src/bootstrap.js` and passes `(req, res)` to `app.handler`. Locally, `backend/server.js` uses the same `getApp()` behind `node:http`. `bootstrap.js` is the only place that reads env vars. It builds the app once per process and caches it, so a warm function reuses its Mongo pool. Vercel limits request bodies to 4.5 MB, so `MAX_BODY_BYTES` is 4 MB. The phone downscales photos to about 0.3 MB.

**Scaling model.** The backend is stateless. Users, sessions, eggs, attempts, finds, reports and photos (stored as binary) all live in MongoDB. The only per-instance state is caches: the station list, MBTA predictions (20s), and the housekeeping throttle. Don't add in-memory state that has to be shared across instances.

**App (`backend/src/app.js`).** `createApp({ db, mbta, verify, geminiKey, geminiModel, now, frontendDir, corsOrigins })` returns `{ handler }`. Everything external is injected, which is how the tests control the clock and fake MBTA and Gemini.
- Routes live in a table of `[method, regex, handler, authMode]`. `authMode` is `'none'` (no token check) or `'optional'` (the bearer token is read if sent, and a bad token returns 401). Handlers that need a player call `requireUser(ctx)`. Each handler gets `ctx = { params, query, body, req, user, sessionId }` and returns plain JSON.
- To return an error, call `fail(status, message)`. The top-level handler turns it into `{ error }`. Anything else becomes a 500.
- **Time comes from the injected `now()`.** Store and compare JS `Date`s from it, and never use `$$NOW` or `new Date()` directly, or the clock-driven tests break.
- Documents use UUID strings as `_id`, and fields are camelCase. The API returns `id`, not `_id`.
- Photos come in as base64 data URLs in JSON (`decodeImage`), are stored in `photos`, and are served at `/photos/<uuid>.jpg` with an immutable cache header. Read them with `{ promoteBuffers: true }` to get a `Buffer`.
- `housekeeping()` (retiring stale eggs) runs lazily on station reads, at most once a minute per instance, measured on the injected clock. There are no background jobs.

**Auth (`backend/src/auth.js`).** Passwords are hashed with scrypt. Register and login each create a `sessions` document per device, holding a SHA-256 hex hash of a random 32-byte bearer token. Sessions last 30 days and slide forward on use (touched at most once an hour), and a TTL index on `expiresAt` deletes them. Logins for unknown usernames still run scrypt against `DUMMY_HASH`. Usernames are unique through `usernameLower`. Each user also has an anonymous `chatName`/`chatNameLower` (random from `game.randomChatName()`, unique, partial index), assigned at sign-up or lazily by `ensureChatName` for older accounts. `nameTaken` checks both fields, so usernames and chat names share a namespace. `POST /api/me/names` changes either. Only the owner sees their chat name (`selfUser` vs `publicUser`). The token never goes in a cookie, so CORS `*` is safe.

**Concurrency (`backend/src/slots.js`, `db.tx`).** All egg-slot changes (place, rotate after a find, retire) run inside `db.tx(fn)`, a MongoDB transaction through `session.withTransaction`, after `lockSlot()`, which `$inc`s a per-slot document in `locks`. Two transactions on the same slot then write-conflict, and the driver retries the loser. `withTransaction` may run `fn` more than once, so `fn` must only touch the database (no Gemini or MBTA calls), and every query inside it must pass `{ session }`. A partial unique index also enforces one active egg per slot. `submitFind` runs the slow Gemini check *outside* the transaction, then closes the round atomically with `findOneAndUpdate({ status: 'open' })`. `finds {userId, eggId}` is unique, and `isDuplicateKey` turns a race into a 409. Transactions need a replica set: Atlas always is one, and the in-memory server is started as one.

**DB (`backend/src/db.js`).** `createDb({ uri, dbName })` connects, creates all indexes (idempotent, on every start) and returns `{ client, db, col, tx, close }`, where `col.<name>` is each collection. `startMemoryMongo()` starts mongodb-memory-server, pinned to mongod 7.0.14 (`MONGOMS_VERSION` overrides it). Add new collections and indexes to `createDb`.

**Blurred eggs (`backend/src/images.js`).** Each level's timer is `LEVELS[].seconds`: 3 minutes, except 2 for Hard and 1 for Impossible. `LEVELS[].blur` is a Gaussian sigma: 0 for Easy to Hard, 6 for Extreme and 16 for Impossible, applied after scaling to fit 1024 px. `createEgg` stores a blurred copy as `eggs.displayPhotoId`, and `displayPhotoId(egg)` makes it lazily for older eggs. Finders only ever get the copy's URL. `submitFind` returns `revealUrl` (the original) after a find, and `profile()` hides other players' find photos (`photoUrl: null`) of eggs that are still active or pooled, unless the viewer has found that egg too. Never send `egg.photoId` to a finder.

**Hiding without a find (`createEgg`, `slots.queueEgg`).** With no `findId`, an empty slot gets the egg live (`placeEgg`); a busy slot gets it as a `pool` egg with `queued: true, activatedAt: null` (`queueEgg`), which `rotateAfterFind`/`retireEgg` bring in later. A player may have at most `game.MAX_QUEUED_EGGS` such waiting eggs, checked before the Gemini screen. The response says `egg.queued`.

**Game rules (`backend/src/game.js`).** Pure functions and constants: `LEVELS`, scoring, `monthKey` (America/New_York), timer bounds and line families. Change game balance here. `finds.month` is stored at insert time so the monthly leaderboard is an indexed `$group`.

**Per-egg clock (`startAttempt`, `endRound`).** A player has one clock per egg: their latest `attempts` doc for it (`latestRound`). `clockState(round, t)` says `running` (open and before `roundEndsAt`, which is `startedAt + limitSeconds + GRACE_SECONDS`, or `endedAt` for a give-up), `retry` (an earlier round ended without a find) or `new`. `startAttempt` resumes a running round (`attempt.resumed: true`, same id, the remaining `secondsLeft`). Otherwise it starts a fresh one, marked `retry: true` after a miss. `scoreFind(..., { retry })` gives a retry no time bonus, the find stores `retry: true`, and the 30 s stamp skips retries. New rounds are inserted in `db.tx` after `lockUser()`, so two taps can't open two clocks. `POST /api/attempts/:id/end` gives up (`status: 'given_up'`, `endedAt`) or marks a timed-out round `expired`. The app calls it on "Give up" and when its timer hits zero. Rounds that are still `open` past their end are treated as expired everywhere, so nothing depends on that call.

**Friend groups (`app.js`, `groups` + `groupMembers` collections).** A group stores `name`, `ownerId`, `inviteCode` (unique, 8 characters from a look-alike-free alphabet) and a denormalized `memberCount`. Joins run in `db.tx`: `lockUser()` (a `locks` doc per player) enforces `MAX_GROUPS_PER_USER`, and a conditional `$inc` on `memberCount` enforces `MAX_GROUP_MEMBERS`. Leaving decrements the count, hands ownership to the earliest `joinedAt`, or deletes the group at 0 members. Group boards reuse `pointsBoard(match)` with `userId: { $in: members }`, and members with no finds are appended unranked.

**Map (`mapLines`, `mapVehicles`, `mapStations`; `frontend/app.js` viewMap).** Albert's live map. `mbta.shapes()` reads `backend/data/shapes.json` (committed; fetched and written once if missing) and `mbta.vehicles()` caches live vehicles for 15 s. Both endpoints answer with empty lists when the MBTA is unreachable. `mapStations` aggregates eggs up, players hunting in the last 15 min (attempts joined to eggs), finds this month, your finds and this month's Keeper per station. Trains are drawn on one canvas and replayed 25 s behind their reports.

**Train lobbies (`backend/src/trains.js`; `trainCheck`, `joinLobby`, `pledge`, lobby chat in `app.js`).** `POST /api/trains/check {lat,lng,accuracy}` stores a `trainSightings` doc (TTL 1 h) when the fix is near a live vehicle (`trains.nearestTrain`, needs `tripId` from `mbta.vehicles()`), and verifies the rider when an earlier sighting of the same trip passes `trains.rodeAlong` (20 s to 5 min apart, train moved ≥120 m, rider moved about the same). Verification is saved as `users.onTrain {tripId, until}` for 10 min. `POST /api/trains/lobby` needs that and creates or joins the trip's lobby (`lobbies.tripId` unique: one lobby per journey). Pledges are by points: `pledge` takes `eggs {level: count}` and an optional `for` (a `lobbyMembers._id`, never a user id), picks the player's oldest unpledged finds of those levels and marks them `finds.pledgedIn` (conditional update, so an egg is pledged once, ever; the find stays, so the egg collection is unchanged). Each egg counts its level's points toward the recipient's `lobbyMembers.pledged`. It runs in `db.tx` after `lockUser` and a `lobby:<id>` lock. When at least `MIN_RIDERS` riders are all at `PLEDGE_TARGET` (100), the lobby is `reached` and `payouts` go out: `kind: 'lobby'` `BONUS_POINTS` per rider, plus `kind: 'lobby_donor'` `DONOR_BONUS_PER_EGG` × `donatedEggs` (both count on leaderboards, profile totals and rider level). `POST /lobbies/:id/help` posts a `help {riderId, need}` chat message (once a minute). `settleLobby` lazily ends a lobby whose trip has been missing from the feed for 3 min (or is over 3 h old); pledged eggs stay pledged. Lobby chat: like group chat, plus `text` through `trains.cleanText` and `reports` (hidden for the reporter at once, for everyone at 3). Clients check every 20 s (`checkTrain` in `startAlerts`) and poll the lobby every 4 s.

**Notifications (`notificationsFor`).** `GET /api/me/notifications` returns your eggs (`egg_hidden`, with photo and `timesFound`), finds of your eggs by others (`egg_found`), `counts {finds, eggsHidden, foundByOthers}`, and `unseen` (finds after `users.notificationsSeenAt`, falling back to `createdAt`). `?summary=1` is the cheap 30 s poll. `POST /api/me/notifications/seen` marks them seen. On the client, `startAlerts()` (from `setSession`) polls, and permanently subscribes `checkArrival` to the GPS watch, which alerts once per station per 30 min with `playable` from `/api/stations`. Alerts go through a toast queue (`notifyPlayer`), plus a browser `Notification` when allowed.

**Group chat (`groupMessages`).** A message is either a `sticker` id that must be in `game.STICKERS` (which `/api/config` also sends to the client; add new ones in `game.js`), or `text` (emoji welcome) passed through `trains.cleanText`: 140 characters, no links, a small word filter. `sendGroupMessage` takes a per-group `seq` with `$inc groups.msgSeq` inside the same `db.tx` as the insert, so messages commit in `seq` order. Messages are anonymous: `publicMessage` returns `name` (the sender's current chat name, looked up at read time) and `mine`, never a user id or username. Clients poll `GET /messages?after=<lastSeq>` every 4s while the chat tab is visible (Vercel functions can't hold WebSockets). There is a rate limit of `CHAT_RATE` per player per group. A TTL index deletes messages after 30 days, and they are also deleted when the group is.

**MBTA (`backend/src/mbta.js`).** V3 API client. Stations are fetched once and cached in `backend/data/stations.json`, which is committed and included in the Vercel function through `includeFiles`. Live `/predictions` show the next train on each station page (display only: every round gets its level's fixed clock; the old race-the-train mode was removed).

**Verification (`backend/src/verify.js`).** Gemini compares the two photos, with a confidence threshold of 0.6. With no key, or when the call fails, it falls back to `{ method: 'honor', match: true }`.

**Frontend (`frontend/`).** "Lookout", a vanilla JS SPA (`app.js`, no framework, no build step) in Albert's ticket design: every egg is a ticket stub, and `html[data-line]` gives the whole app the colour of the line you're at (CSS tokens `--here`, `--here-deep`, `--here-ink`; Orange uses dark text). Purple `--stamp` marks game results. The design tokens live at the top of `styles.css`; reuse the existing classes (`.tk`, `.tk-top`/`.tk-perf`/`.tk-bottom`, `.band`, `.stub`, `.ranks`, `.seg` with `aria-selected`, `.btn-ink`/`.btn-primary`/`.btn-ghost`, `.stamp`) instead of adding new looks.
- Hash routes: `#/` (Here: location picks the station within 400 m), `#/stations`, `#/station/:id`, `#/play`, `#/hide`, `#/leaderboard`, `#/user/:id`, `#/notifications`, `#/profile` (Profile: names, activity from `profile().activity`, stamps, finds, devices), `#/map`, `#/groups`, `#/group/:id`, `#/join/:code`. Clean up per view with `every()` / `onCleanup()`, which `render()` clears.
- The HUD (rank, points, rival) comes from `/api/leaderboard`, and rider level, daily challenge and stamps from `/api/me/progress`.
- `config.js` sets `window.EGG_API_BASE` (empty means same origin, as on Vercel), and every request and photo URL goes through `apiUrl()`. The session (`{ user, token }`) is kept in `localStorage['egg-session']`. On boot the app calls `/api/auth/me`, and any 401 signs this device out. After sign-up, a pending `#/join/CODE` hash is kept so invite links work for new players. `serve.js` is a zero-dependency static server that rewrites `config.js` from the `API_BASE` env var.

**Progress (`GET /api/me/progress`, `game.js`).** Rider level (`RIDER_LEVELS`), one daily challenge for everyone (`challengeFor(dayKey)`, Boston days) and 8 stamps. All of it is derived from `finds`, `payouts` (lobby bonuses) and `eggs`, with nothing extra stored. `submitFind` also returns `firstFind` (the egg's first ever find, read under the slot lock).

**Tests (`backend/test/api.test.js`).** End-to-end tests over HTTP against a real MongoDB: an in-memory replica set, or `TEST_MONGODB_URI` with a random database that is dropped afterwards. They use a fake MBTA, a controllable `nextVerify` and a mutable `clock`. `user(name)` registers and returns `{ id, username, token }`, and `call/ok(path, body, as)` sends that token. `db.col.*` is available for asserting on stored documents. New behavior is normally tested the same way.
